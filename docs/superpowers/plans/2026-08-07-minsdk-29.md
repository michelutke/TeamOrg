# Android minSdk 29 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lower the Android minSdk floor from 34 to 29, verified by a new API 29 instrumented-test job in CI.

**Architecture:** Two PRs. PR 1 (Tasks 1–4) builds an instrumented test harness and an emulator CI job running at API **34** — the current floor — so the harness is proven green on a known-good configuration. PR 2 (Tasks 5–6) flips minSdk to 29 and the emulator to API 29; because that diff is two numbers plus a resource move, a red run can only mean Android 10 breakage.

**Tech Stack:** Kotlin Multiplatform, Compose Multiplatform 1.10.1, AGP 8.13.2, Ktor 3.3.3 server, Koin 4.1.1, androidx.test + Compose UI test, GitHub Actions with `reactivecircus/android-emulator-runner`.

**Spec:** `docs/superpowers/specs/2026-08-07-minsdk-29-design.md`

## Global Constraints

- Target floor is **API 29** (Android 10). Do not go below — the hard library floor is 26 (`otel-5.7.6`) and 29 keeps margin.
- `compileSdk` and `targetSdk` stay at **36**. Do not change them.
- **No** core-library desugaring, **no** new `SDK_INT` guards, **no** dependency version changes, **no** notification-permission work, **no** `foregroundServiceType` work. The investigation proved all of these unnecessary; adding them is scope creep.
- The single existing `SDK_INT` guard at `composeApp/src/androidMain/kotlin/ch/teamorg/ui/theme/DynamicColorScheme.android.kt:12` stays exactly as-is.
- The pre-existing lint error `MissingClass: ch.teamorg.ui.TestActivity` (`composeApp/src/androidMain/AndroidManifest.xml:16`) is **out of scope**. Do not fix it. `lintDebug` will keep failing on it; that is expected.
- `SWISSVOLLEY_SYNC_ENABLED=false` is **mandatory** in any CI server invocation. `server/src/main/kotlin/ch/teamorg/infra/SwissVolleySyncJob.kt:25` disables the job only on an explicit `false`; the default starts a background poller against the real `https://api.volleyball.ch`.
- Never add `Co-Authored-By` or AI-authorship hints to commits.
- Never use `git rebase`; use `git merge`.
- SharedPreferences file name for auth state is exactly `teamorg_prefs` (`shared/src/androidMain/kotlin/ch/teamorg/di/SharedModule.android.kt:41`).
- Emulator reaches the host-side backend at `http://10.0.2.2:8080`. This is already whitelisted for cleartext in the debug variant (`shared/src/commonMain/kotlin/ch/teamorg/data/network/HttpClientFactory.kt:15`, and the `androidDebug` network security config from commit `e45c32a`). Do not add new cleartext config.

## Deviation from the spec (read before Task 4)

The spec placed the emulator job inside `.github/workflows/test.yml`. **Do not do that.** GitHub's `on: pull_request: paths:` filter is workflow-scoped, not job-scoped — adding path filters to `test.yml` would silently path-filter the existing backend, shared, and Android unit-test jobs too, which is a regression in coverage.

The emulator job therefore goes in a **new workflow file**, `.github/workflows/test-android-emulator.yml`, with its own `on:` block and its own path filter. Everything else about the job matches the spec.

## Task 1: Instrumentation runner and cold-start smoke test

Wires the empty `androidInstrumentedTest` source set and adds the highest-value test: init-time API breakage is the dominant failure mode for a minSdk change.

**Files:**
- Modify: `gradle/libs.versions.toml`
- Modify: `composeApp/build.gradle.kts` (`defaultConfig` block near line 106; `androidInstrumentedTest` dependencies near line 66)
- Create: `composeApp/src/androidInstrumentedTest/kotlin/ch/teamorg/TestPrefs.kt`
- Create: `composeApp/src/androidInstrumentedTest/kotlin/ch/teamorg/AppLaunchTest.kt`

**Interfaces:**
- Consumes: nothing (first task)
- Produces: `ch.teamorg.TestPrefs.clear(): Unit` — used by Tasks 2 and 3.

**Background you need:** `AuthViewModel.checkAuthState()` (`composeApp/src/commonMain/kotlin/ch/teamorg/auth/AuthViewModel.kt:26`) makes **no network call** when no token is stored — it goes straight to `AuthState.Unauthenticated`, which renders the login screen. That is why this test needs no backend. It only holds if SharedPreferences is cleared *before* `MainActivity` launches, which is why the test uses `createEmptyComposeRule()` plus a manual `ActivityScenario.launch` rather than `createAndroidComposeRule<MainActivity>()` — the latter launches the activity during rule evaluation, before any `@Before` method could clear prefs.

The app shows an animated splash before the login screen, so the test must wait rather than assert immediately.

```kotlin
package ch.teamorg

import android.content.Context
import androidx.test.platform.app.InstrumentationRegistry

/**
 * The app persists its JWT in SharedPreferences, so auth state survives between
 * instrumented tests in the same process. Every test that cares about the starting
 * screen must clear it BEFORE the activity launches.
 */
object TestPrefs {
    fun clear() {
        InstrumentationRegistry.getInstrumentation().targetContext
            .getSharedPreferences("teamorg_prefs", Context.MODE_PRIVATE)
            .edit()
            .clear()
            .commit()
    }
}
```

## Task 2: Picker contract tests

The image and document pickers are the code most likely to behave differently across API levels, because `ActivityResultContract.createIntent` has version-conditional branches internally.

**Files:**
- Create: `composeApp/src/androidInstrumentedTest/kotlin/ch/teamorg/PickerContractTest.kt`

**Interfaces:**
- Consumes: nothing from Task 1 (the runner wiring from Task 1 must be in place, but no symbols are shared)
- Produces: nothing consumed by later tasks

**Why this asserts Intent *shape*, not Intent *resolution*:** the obvious test is `intent.resolveActivity(packageManager) != null`. Do not write that. Android 11+ package-visibility filtering can make that return null for reasons unrelated to API level, producing a test that fails without a real regression. Asserting what `createIntent` produces tests the version-conditional logic directly and is stable across API levels.

Create `composeApp/src/androidInstrumentedTest/kotlin/ch/teamorg/PickerContractTest.kt`:

```kotlin
package ch.teamorg

import android.content.Intent
import androidx.activity.result.contract.ActivityResultContracts
import androidx.test.ext.junit.runners.AndroidJUnit4
import androidx.test.platform.app.InstrumentationRegistry
import org.junit.Assert.assertArrayEquals
import org.junit.Assert.assertEquals
import org.junit.Assert.assertTrue
import org.junit.Test
import org.junit.runner.RunWith

/**
 * The pickers in ImagePicker.android.kt and DocumentPicker.android.kt rely on
 * ActivityResultContracts, whose createIntent implementations branch on API level.
 * These assertions pin the Intent each contract produces on the device under test.
 *
 * Note: intentionally does NOT assert resolveActivity(...) != null — package
 * visibility filtering on API 30+ can null that out for reasons unrelated to the
 * API floor, which would make this test lie.
 */
@RunWith(AndroidJUnit4::class)
class PickerContractTest {

    private val context = InstrumentationRegistry.getInstrumentation().targetContext

    @Test
    fun getContent_producesGetContentIntentForImages() {
        val intent = ActivityResultContracts.GetContent().createIntent(context, "image/*")

        assertEquals(Intent.ACTION_GET_CONTENT, intent.action)
        assertEquals("image/*", intent.type)
        assertTrue(
            "GetContent must request an openable document",
            intent.categories?.contains(Intent.CATEGORY_OPENABLE) == true
        )
    }

    @Test
    fun openDocument_producesOpenDocumentIntentWithSpreadsheetMimeTypes() {
        val mimeTypes = arrayOf(
            "text/csv",
            "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
        )

        val intent = ActivityResultContracts.OpenDocument().createIntent(context, mimeTypes)

        assertEquals(Intent.ACTION_OPEN_DOCUMENT, intent.action)
        assertTrue(
            "OpenDocument must request an openable document",
            intent.categories?.contains(Intent.CATEGORY_OPENABLE) == true
        )
        assertArrayEquals(mimeTypes, intent.getStringArrayExtra(Intent.EXTRA_MIME_TYPES))
    }

    @Test
    fun takePicturePreview_producesCameraStillImageIntent() {
        val intent = ActivityResultContracts.TakePicturePreview().createIntent(context, null)

        assertEquals("android.media.action.IMAGE_CAPTURE", intent.action)
    }
}
```

```kotlin
package ch.teamorg

import java.net.HttpURLConnection
import java.net.URL

/**
 * Creates accounts directly against the backend so a login test does not depend on
 * the register test having run first. Uses HttpURLConnection to keep the
 * instrumented test source set free of extra dependencies.
 *
 * 10.0.2.2 is the emulator's alias for the host machine's loopback.
 */
object BackendSeed {

    private const val BASE_URL = "http://10.0.2.2:8080"

    fun register(email: String, password: String, displayName: String) {
        val body = """{"email":"$email","password":"$password","displayName":"$displayName"}"""
        val connection = (URL("$BASE_URL/auth/register").openConnection() as HttpURLConnection).apply {
            requestMethod = "POST"
            doOutput = true
            connectTimeout = 10_000
            readTimeout = 10_000
            setRequestProperty("Content-Type", "application/json")
        }

        try {
            connection.outputStream.use { it.write(body.toByteArray()) }
            val code = connection.responseCode
            check(code == 200 || code == 201) {
                val error = connection.errorStream?.bufferedReader()?.readText().orEmpty()
                "Seeding register failed with HTTP $code: $error"
            }
        } finally {
            connection.disconnect()
        }
    }
}
```

```kotlin
import androidx.compose.ui.test.junit4.createEmptyComposeRule

import androidx.compose.ui.test.onNodeWithTag

import org.junit.Rule
import org.junit.Test
import org.junit.runner.RunWith

/**
 * Register and login driven through the real UI against a live backend on
 * http://10.0.2.2:8080. Requires the server to be running.
 */
@RunWith(AndroidJUnit4::class)
class AuthFlowTest {

    @get:Rule
    val composeRule = createEmptyComposeRule()

    private val password = "instrumented-pw-1" // gitleaks:allow (disposable test-fixture password, not a real credential)

    /** Unique per run so repeated runs never collide on the email-uniqueness constraint. */
    private fun uniqueEmail(prefix: String) = "$prefix-${System.currentTimeMillis()}@example.com"

    private fun awaitTag(tag: String, timeoutMillis: Long = 30_000) {
        composeRule.waitUntil(timeoutMillis) {
            composeRule.onAllNodesWithTag(tag).fetchSemanticsNodes().isNotEmpty()

    @Test
    fun register_newAccount_landsOnEmptyState() {

        val email = uniqueEmail("register")

        ActivityScenario.launch(MainActivity::class.java).use {
            awaitTag("btn_navigate_register")
            composeRule.onNodeWithTag("btn_navigate_register").performClick()

            awaitTag("tf_display_name")
            composeRule.onNodeWithTag("tf_display_name").performTextInput("Instrumented Coach")

            composeRule.onNodeWithTag("tf_password").performTextInput(password)
            composeRule.onNodeWithTag("tf_confirm_password").performTextInput(password)
            composeRule.onNodeWithTag("btn_create_account").performClick()

            // A brand-new user has no team, so navigation lands on EmptyState.
            awaitTag("btn_create_team_or_club")
            composeRule.onNodeWithTag("btn_create_team_or_club").assertIsDisplayed()
        }
    }

    fun login_withSeededAccount_landsOnEmptyState() {

            composeRule.onNodeWithTag("tf_password").performTextInput(password)

            awaitTag("btn_create_team_or_club")

        }
    }
}
```

- [ ] **Step 1: Create the workflow**

Create `.github/workflows/test-android-emulator.yml`:

```yaml
name: Android Instrumented Tests

permissions:
  contents: read

# Separate workflow rather than a job in test.yml: `on.paths` is workflow-scoped, so
# putting these filters in test.yml would silently path-filter the backend, shared, and
# unit-test jobs too. The emulator is the most expensive job in CI, so it only runs when
# Android-relevant code changed — matching the policy set in cbc785c.
on:
  pull_request:
    branches: [ main ]
    paths:
      - 'composeApp/**'
      - 'shared/**'
      - 'gradle/**'
      - '.github/workflows/test-android-emulator.yml'
  push:
    branches: [ main, 'release/**' ]

concurrency:
  group: android-emulator-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test-android-emulator:
    name: Android Instrumented Tests (API 34)
    runs-on: ubuntu-latest
    timeout-minutes: 30
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_DB: teamorg_test
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
        options: >-
          --health-cmd "pg_isready -U test"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
        ports:
          - 5432:5432
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'

      - uses: gradle/actions/setup-gradle@v3

      # Without this the emulator cannot use hardware acceleration and never boots.
      - name: Enable KVM
        run: |
          echo 'KERNEL=="kvm", GROUP="kvm", MODE="0666", OPTIONS+="static_node=kvm"' \
            | sudo tee /etc/udev/rules.d/99-kvm4all.rules
          sudo udevadm control --reload-rules
          sudo udevadm trigger --name-match=kvm

      - name: Create dummy google-services.json
        run: |
          cat > composeApp/google-services.json << 'GSEOF'
          {
            "project_info": { "project_number": "000000000000", "project_id": "dummy-ci", "storage_bucket": "dummy-ci.appspot.com" },
            "client": [{ "client_info": { "mobilesdk_app_id": "1:000000000000:android:0000000000000000", "android_client_info": { "package_name": "ch.teamorg" } }, "oauth_client": [], "api_key": [{ "current_key": "dummy-key-for-ci" }], "services": { "appinvite_service": { "other_platform_oauth_client": [] } } }],
            "configuration_version": "1"
          }
          GSEOF

      - name: Build server
        run: ./gradlew :server:installDist

      # SWISSVOLLEY_SYNC_ENABLED must be false: SwissVolleySyncJob only skips on an
      # explicit false, so the default would poll the real api.volleyball.ch from CI.
      - name: Start server
```
